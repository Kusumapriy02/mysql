JOINS: a join in MySQL is used to combine rows from two or more tables based on relatyed columns
example: employee details
department--->department details
if you want to see which employee belongs to which department you need to join these two tables 
why do we need joins ?
to fetch data from multiple tables in a single query.
to reduce data dupilication (instead of keeping everything one table)
to implement relationships like(one-to-one,one-to-many,many-to-many,many-to-one) in databases 
4.to generate reports and analytics combing different datasets
========================================
inner join():returns only the rows that have matching values in both tables.
syntax: select colums from table1 inner join table2 on table1.common_column=table2.common_column;
left join():returns all rows from the left table and matched rows from the right table.if no match, nullvalues appear for right table columns.
syntax: select colums from table1 left join  table2 on table1.common_column=table2.common_column;

right join():returns all rows from theright table and matched rows from the left table.if no match, nullvalues appear for left table columns.
syntax: select colums from table1 right join  table2 on table1.common_column=table2.common_column;


full join(): to simulate use the union of lesft join and right join
syntax: select columns from table1 left join table2 on table1.commom_column =table2.common_colum union elect colums from table1 right join  table2 on table1.common_column=table2.common_column;


cross join():returns cartesian product ---> every row from the fgirst table with row from the second table
syntax:
select columns from table1 cross join table2;

self join():a table joined with itself
syntax:
select a.columns,b.columns
from table1 a inner join table b on a.common_column = b.common_column;

VIEWS:A view is a virtual table in MySQL built from the result of sorted select statyement it looks and behaves like regular table when you query it.
you can select from it, filter it and join it .but it doesn't store any data on its own. every time view is queied ,MySQL runs its underlying slect statement against in real tables and returns the result
why do we need views
simplify complex queries
reuse query logic
data security
logical data independence


advantages:
========================================================
security
reusability
simplicity
consistency
maintainability
custom data presentation

creating views
==================================================
create view view_name as select columns from table where condition 


altering view
================================================
alter view view_name as select new_columns from new_tables.

dropping view
=================================================
drop view view_name ;
drop view if exsists view_name;
